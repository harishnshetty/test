#### [00:08:08 → 00:14:31] Linux Interview Questions  
- **Linux flavors used:** Ubuntu, CentOS, Amazon Linux are common in enterprise environments.  
- **File ownership and permissions:**  
  - Use `chown` to change ownership  
  - Use `chmod` to modify permissions (e.g., adding execute permission)  
  - Use `sudo` for elevated privileges when necessary  
- **Managing processes:**  
  - `ps` command to list processes  
  - `top` command to monitor CPU and memory usage  
  - `kill` command to stop processes  
- **SSH:** Secure remote shell to connect and manage remote Linux machines using key-based or password authentication (`ssh -i key.pem user@host`).  
- **Checking memory and CPU:**  
  - `free -h` for memory  
  - `top` for CPU and memory monitoring  
- **Cron jobs:** Scheduled tasks automating repetitive jobs using `crontab -e` with syntax specifying time intervals. Example: backing up MongoDB database.  
- **Alias in Linux:** Shortcut commands to reduce typing effort (`alias ll='ls -la'`). Useful for frequently used long commands.

#### [00:14:31 → 00:19:19] Networking Interview Questions  
- **DNS (Domain Name System):** Translates human-readable domain names (example.com) into IP addresses. Supports multiple record types (A, CNAME, MX, TXT). AWS Route53 is an example DNS service.  
- **NAT (Network Address Translation):** Translates private IP addresses to a public IP address, allowing multiple private servers to share a single public IP and enhancing security by hiding internal network structure.  
- **TCP vs UDP:**  
  | Feature            | TCP                                      | UDP                                  |
  |--------------------|------------------------------------------|-------------------------------------|
  | Connection type    | Connection-oriented, reliable             | Connectionless, faster but unreliable|
  | Error checking     | Yes, with retransmission                   | No error recovery                    |
  | Use cases          | File transfer, web browsing, emails       | Real-time streaming, online gaming  |
- **OSI Model:** Seven layers with examples:  
  - Application Layer (7) — Application Load Balancer  
  - Transport Layer (4) — Network Load Balancer  
- **Firewall:** Security device controlling incoming/outgoing network traffic based on rules; in AWS this is often implemented via Security Groups. Protects from unauthorized access and attacks like DDoS.  
- **Ping:** Tests network connectivity by sending ICMP echo requests and measuring response times.  
- **ifconfig/ipconfig:** Display network configuration details such as IP and MAC addresses on Linux/Windows respectively.

#### [00:19:19 → 00:26:15] Git Interview Questions  
- **Git:** Distributed version control system to track changes and facilitate collaboration; essential for CI/CD pipelines.  
- **Basic Git workflow:**  
  1. Clone repository (`git clone `)  
  2. Modify files locally  
  3. Stage changes (`git add `)  
  4. Commit changes (`git commit -m "message"`)  
  5. Push changes to remote (`git push origin `)  
- **Reverting commits:** Using `git revert ` to undo changes safely, followed by pushing the revert commit.  
- **Branches:** Separate lines of development allowing parallel work on features without affecting the main codebase. Always work in feature branches and avoid pushing directly to main/master branch.

#### [00:26:15 → 00:31:24] Cloud Computing &amp; Infrastructure as Code (IaC)  
- **Cloud familiarity:** AWS, Azure, GCP—mention any you have experience with.  
- **VPC (Virtual Private Cloud):** Isolated virtual network within a cloud provider to deploy resources securely with custom IP ranges.  
- **Public vs Private Subnet:**  
  | Subnet Type   | Internet Access          | Typical Resources              | Connected To              |
  |---------------|-------------------------|-------------------------------|---------------------------|
  | Public Subnet | Directly accessible      | Web servers, load balancers    | Internet Gateway          |
  | Private Subnet| No direct internet access| Databases, internal services   | NAT Gateway               |
- **Reserved Instance vs Spot Instance:**  
  | Instance Type       | Usage                            | Cost Efficiency              | Risk                     |
  |---------------------|---------------------------------|------------------------------|--------------------------|
  | Reserved Instance   | Long-term workloads              | Lower cost due to commitment  | Stable availability       |
  | Spot Instance       | Short-term, interruptible tasks  | Cheapest option               | Can be terminated anytime |
- **CloudFormation:** AWS’s Infrastructure as Code tool to provision and manage resources using JSON/YAML templates and stacks.  
- **Terraform vs Ansible:**  
  | Tool      | Primary Use                  | Functionality                      | Configuration Format   |
  |-----------|------------------------------|----------------------------------|------------------------|
  | Terraform | Infrastructure provisioning  | Defines desired state of infra   | HCL (HashiCorp Config) |
  | Ansible   | Configuration management     | Automates server configuration   | YAML Playbooks         |
- **Playbook:** YAML file defining tasks to be executed on remote servers via Ansible.  
- **Terraform State File:** Tracks current infrastructure state to apply accurate changes; commonly stored in remote backends like S3 for collaboration.

#### [00:31:24 → 00:35:09] Containers &amp; Containerization  
- **Virtualization vs Containerization:**  
  - Virtualization creates full guest OS on VMs (heavyweight).  
  - Containerization shares the OS kernel but isolates applications in lightweight containers.  
- **Docker solves:**  
  - Application portability, environment consistency, isolation, and security.  
- **Dockerfile:** Script defining steps to build Docker images (instructions like base image, commands to run, ports to expose).  
- **Docker workflow:** Write Dockerfile → Build image → Run container → Container runs app in isolated environment.  
- **Container orchestration:** Tools like Kubernetes, Docker Swarm, Mesos, Nomad help manage multiple containers at scale.  

---

#### [00:35:09 → 00:41:34] CI/CD (Continuous Integration/Continuous Deployment)  
- **CI:** Automatically build and test code changes frequently to detect issues early.  
- **CD:** Automatically deploy code changes to staging or production environments.  
- **CI/CD tools:** Jenkins, GitLab CI, Travis CI, GitHub Actions, etc.  
- **Building a CI/CD pipeline:**  
  1. Use Git repository as source  
  2. Automate build, test, deployment tasks  
  3. Promote builds through staging before production  
- **Automating deployment:** Use scripting (Bash/Python) combined with CI/CD tools for fully automated pipelines.

#### [00:41:34 → 00:42:15] Deployment &amp; Final Tips  
- **Environments:**  
  | Environment    | Purpose                                  |
  |----------------|------------------------------------------|
  | Development    | Code writing and local testing           |
  | Staging        | Pre-production testing environment       |
  | Production     | Live environment for end-users           |
- **Deployment strategies:**  
  - **Blue-Green:** Two identical environments; switch traffic between them to deploy new versions with easy rollback.  
  - **Canary:** Release new versions to a small subset of users first, then gradually roll out if stable.  
- **Deployment challenges:** Example - handling sudden traffic spikes by scaling infrastructure and optimizing queries.  
- **Scaling applications:** Use AWS Auto Scaling Groups, Kubernetes Horizontal Pod Autoscaler, or scale deployments vertically/horizontally.  
- **Rollback &amp; Disaster Recovery:** Roll back to previous versions via container orchestration tools or deployment strategies; monitor and alert with tools like Prometheus.  
- **Interview tip:** Always ask the interviewer questions about the role, team, projects to demonstrate interest.
